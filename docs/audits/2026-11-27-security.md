# Security, 2026-11-27 (0.8.4)

## Why

After 0.8.3 the author asked on 11-24 for a proper security audit of our
own, and then for security-review-guide.md to be refined from it. The
base was 3204fa2, released as 0.8.3. The fixes are on main up to
b0d9102, for 0.8.4.

## Scope

How other apps on the phone reach Rustrx (D-Bus, notification actions,
the share target, URL handlers, push); the network, logins, devices and
calls; secrets, stores, logs and data at rest; the C ABI between core and
C++, command input, panics and resource use; and content from other
Matrix users and servers (message HTML, pictures, media, files, names,
links). The guide's sixteen open questions were each answered in the
area they belong to.

Not in scope: an independent review, fuzzing beyond the two harnesses
below, and anything that needs another app installed on a phone.

## Method

All agents were LLM agents working under the author's direction. This is
not an independent review.

- Five agents read the tree at 3204fa2, none of them editing: IPC (other
  apps), network, secrets, FFI, content. Each ranked its findings by who
  can do what to whom, marked its guesses, and answered the guide's
  questions in its area: confirmed problem, not a problem (why), or
  unknown (what would settle it).
- Outside sources they read: matrix-sdk 0.19.1 and its crates, reqwest
  0.13.5, the sources of lipstick, sailjail, sailfish-secrets and
  mapplauncherd (their master branches, not the versions on the phones),
  Qt 5.6's StyledText, image reader and plugins, and the Sailfish OS 5.1
  SDK target and a 5.1 port image for the permission files, the session
  bus policy, journald and backups. Jolla's own images may differ; each
  such point says so.
- Small programs outside the repo: the message HTML path built on the
  host and fed to Qt's StyledText parser; `Mp4::read` and `strip` under
  ASan and UBSan with 3 million mutated inputs (no report); the QR decoder
  with 280 000 synthetic noisy frames (3 panics); `cargo audit` and
  `cargo deny` against `core/Cargo.lock`.
- No device was used for the analysis. The findings went to the author
  in one list; whatever changed nothing the user sees was fixed at once
  (67019c7), the rest after his decisions (a5266e1, 5131d6c). Three
  later commits corrected the fixes themselves (c8de0de, 4833d40,
  b0d9102, below); c8de0de and b0d9102 came from tests on the phones.

Ids. Each report kept its prefix: IPC, NET, SEC, FFI, UC (content). The
forward of an encrypted file into an unencrypted room had no id in its
report; it is UC15 here. IPC1c is the stale Answer, part (c) of IPC1,
which the author decided on its own. The author's decisions are DEC1 to
DEC25, in the order he answered them. The ledger beside this file has
the reports' findings about Rustrx, IPC1c and UC15 on their own lines,
and the decisions. Ids that are missing from the sequence belong to
findings about the platform (see "For Jolla").

## What was found

Medium, by area:

- **Other apps (IPC1, IPC2).** Notification actions were an
  unauthenticated "act as the user" API: any process of the user could
  send a reply, react, mark read, answer a ringing call (which opens the
  microphone) or end the stand-in for good. The push connector name
  could be taken first by another app, which would then get the token,
  the endpoint, every push and the text typed into Reply.
- **Network (NET-1 to NET-3).** Element Call, remote code, got every
  widget capability it asked for. Link a new device opened the consent
  page that the new device supplied, unchecked. Plain http homeservers
  were taken silently, also from `.well-known` and QR codes.
- **Secrets (SEC1).** The privacy settings (receipts, typing, presence,
  notification text, stranger invites, the last room) lived in dconf,
  not in Rustrx's own settings file.
- **FFI (FFI-1, FFI-2).** The QR decoder (rqrr) panicked on some noisy
  frames, which aborted the app. One message could start about 2000
  custom emoji downloads, without limit in number, size or disk.
- **Content (UC1 to UC3).** Nested lists made Qt 5.6's StyledText draw
  quadratically: 12.8 KB of message cost 585 MB, and with "reopen last
  room" the app crashed at every start. The sender's MIME type chose the
  image decoder, so every Qt image plugin was reachable without a tap.
  No pixel limit before decoding: a 281 KB interlaced PNG cost 531 MB.

Low and info findings are in the ledger. Among them: the distributor
chosen by a name suffix (IPC3), anyone in a shared room able to ring the
phone (NET-4), the phone's IP addresses in call candidates by default
(NET-8), a lost key in Secrets deleting the stores (SEC3), collected logs
readable in Downloads (SEC8), log lines with URL queries and server
bodies (SEC7), key export through a planted link (FFI-4), and openFile's
denylist bypassed by the exported name (UC5).

Answers to the guide's questions, in short: Q1 and Q2 confirmed (IPC1,
IPC2, IPC6); Q4 confirmed (UC5); Q5 and Q6 not a problem, with two edges
(SEC3, SEC9); Q7 confirmed (NET-3); Q8 confirmed, low (SEC7, FFI-8); Q9
not a problem on the 5.1 image (root and the journal groups only); Q10
confirmed (FFI-6, UC6); Q11 partly (IPC5); Q12 not a problem as asked,
but the consent page next to it was (NET-2); Q13 confirmed for the QR
decoder only (FFI-1); Q14 confirmed only at logout (SEC5); Q15 not a
problem on the 5.1 image (no backup unit reads Rustrx's folders); Q16
confirmed (NET-1). The guide now says this at each question.

## What was done

- **67019c7**, the fixes nobody sees: the notification actions checked
  against what Rustrx has up (IPC1); the stand-in handed over to a second
  launch with a secret (IPC6); shared files each in a folder of their
  own, written new, under one size cap (IPC5); the privacy settings out
  of dconf into Rustrx's own settings file, the debug switches in dconf
  acting only while the dev-commands file exists (SEC1); no new store
  key when Secrets contradicts itself, old stores moved aside (SEC3);
  session.json dropped only when the key really cannot open it (SEC9);
  the core's key copies wiped (SEC13); Element Call's capabilities as an
  allowlist (NET-1); the call peer fixed before the answer (NET-5); the
  peer's SDP, candidates and streams bounded (NET-9); the password field
  emptied (NET-13); the 40 MP limit before decoding and notification
  icons at 256 px (UC3, UC13); GStreamer's playlist demuxers off (UC4);
  renderHtml about twenty times faster on long input (UC9); the QR
  decoder's panic caught (FFI-1); cache names as SHA-256 of their ids
  (FFI-6, UC6); the export into Downloads without the folder race
  (FFI-5); log redaction in core and app (SEC7); voice and outgoing
  copies swept (SEC4); url 2.5.9 (FFI-11); the doc drift (FFI-13).
- **a5266e1**, the author's decisions on login, keys and logs: plain
  http only at home (NET-3), the consent page only on the account
  service's host (NET-2), another person's verification request a
  notification first (NET-6), a browser login into another account
  undone (NET-7), a random Secrets collection and a "Secrets refused"
  state (SEC2), the ask before starting over with a new key (SEC3), the
  wipe on a hard logout only (SEC6), logs to the share sheet from the
  cache (SEC8), key exports written privately and numbered (FFI-4).
- **5131d6c**, the author's decisions on push, calls, content and media:
  Reply to the app's own name and the connector name proved by
  `NameProof` (IPC2), a stale Answer opening the room (IPC1c), the
  distributor by its exact name with a yes for a new one (IPC3),
  "Rustrx could not start" once per boot (IPC6), Look up for links from
  other apps (IPC7), rings only in rooms of up to two (NET-4), relay-only
  calls by default (NET-8), "Message too long to show" (UC1), only JPEG,
  PNG, GIF and WebP decoded by their bytes (UC2), emoji caps (FFI-2),
  "Large file, tap to load" (FFI-3), files opened only when name and
  bytes agree on a safe kind (UC5), the user ID beside a shared display
  name (UC7), the ask for a link whose text names another host (UC8), a
  fresh unencrypted copy for a forward out of an encrypted room (UC15).
- **2c7c4a5**, before the decisions: the notification buttons went to
  the app's own name when push is off or no distributor is found (a first
  half of IPC2).

Three corrections to the fixes:

- **c8de0de.** The 67019c7 rule took actions only from the owner of the
  notification server. Notification actions reach Rustrx from a
  short-lived helper process of the user, not from the notification
  server, so Answer on a ring with Rustrx closed was refused. The author chose the
  same-user rule: any caller of this Unix user, asked per call, and only
  for a notification Rustrx has up.
- **4833d40.** With that rule any app of the user could end the stand-in
  (a residual risk named with c8de0de).
  Quit is now taken only while the stand-in's background line is up, and
  5 s after it closes.
- **b0d9102.** On the C2 without a distributor the sandbox may not own
  the connector name, and the free name was taken for a squat: push
  paused and the red hint showed for everyone without Foghorn. Only a
  name with an owner that fails the proof counts now. The same commit
  makes a stand-in that finds Rustrx running leave at once.

## Decided by the author

- **DEC1 (UC1).** A length cap rather than a list depth cap: what
  StyledText would draw is counted, and above 200 000 characters the
  message shows "Message too long to show".
- **DEC2 (NET-3).** Plain http only for the phone itself and the home
  network.
- **DEC3 (NET-2).** The consent page opens only on the account service's
  host; anything else cancels with a message.
- **DEC4 (IPC2).** Reply to the app's own name; a warning in red in
  Settings, under the push choice, when another app holds the name.
- **DEC5 (UC2).** Inline only what the file really is.
- **DEC6 (IPC1c).** A stale Answer opens the room. 67019c7 first made it
  do nothing.
- **DEC7 (IPC3).** The exact name, and a new distributor needs a yes
  once; the dialog text was ours to write ("Use %1 for push?").
- **DEC8 (IPC6).** The push-woken process says so, once per boot.
- **DEC9 (IPC7).** A Look up button first, for links from other apps.
- **DEC10 (NET-4).** Rings only in rooms of two; in groups the
  notification only.
- **DEC11 (NET-6).** Ask first.
- **DEC12 (NET-7).** Refuse, with a message.
- **DEC13 (NET-8).** Relay-only by default.
- **DEC14 (SEC2).** The texts were ours to write.
- **DEC15 (SEC3).** If the old store may be recoverable, ask before
  starting over.
- **DEC16 (SEC5).** No change. Lipstick's notification history is not
  touched at logout: a user who turns Rustrx on only now and then may
  want to catch up on the notifications that came while it was closed.
- **DEC17 (SEC6).** Wipe on a hard logout, keep on a soft one. A hard
  logout is defined narrowly in `checks::hard_logout`: no refresh token,
  `soft_logout` false, a server without an account service, and a
  classic (not OAuth) session. A refused refresh never counts, because
  Synapse answers a `session.json` two rotations behind the same way as a
  removed device, and on a server with an account service an expiry and
  a sign-out elsewhere look the same. So the 3aab50e behaviour stays for
  every case where the two cannot be told apart.
- **DEC18 (SEC8).** The share sheet; no copy in Downloads.
- **DEC19 (FFI-2).** Caps; an emoji over the cap shows as its name.
- **DEC20 (FFI-3).** A cap by the size the event states: "Large file,
  tap to load".
- **DEC21 (FFI-4).** A second export the same day gets a new name.
- **DEC22 (UC5).** Open only the known safe kinds; offer to save the
  rest.
- **DEC23 (UC7).** The user ID beside ambiguous names.
- **DEC24 (UC8).** Ask before opening such a link.
- **DEC25 (UC15).** Upload a fresh unencrypted copy; the users are
  expected to know what they are doing.

## For Jolla

Findings about the platform itself went to Jolla separately.

## Left open

- **Info findings not done:** the dev hook still opens a password login
  once the flag file exists (IPC8); the panic hook logs the payload
  (FFI-8); a command handler deletes the file it is given (FFI-9); an
  event above Qt's JSON limit vanishes without a log line (FFI-10); no
  `deny.toml` or `cargo deny` step (FFI-11); no catch around the C++
  callback body (FFI-12); the shared runtime's two workers (FFI-7,
  reasoned, not measured); a bare `&` in StyledText text (UC10); `&amp;`
  kept in hrefs (UC11); the first textual attribute match and the greedy
  `<mx-reply>` removal (UC12); the journal copy while the debug log is
  off (SEC11); file modes (SEC14); the common gateway after any probe
  failure (NET-11); the login page showing an error text a local process
  set (NET-10).
- **Parts of fixed findings:** a room opened by a link or notification
  action from outside still sends its read receipt without a touch
  (IPC7); `avatars/` is not swept by age, and the 20 MB cap trusts the
  size the event states (FFI-3); `media/` keeps decrypted copies outside
  the store's encryption (SEC4, by design since CB8); `store-lost-*`
  folders are never cleaned (SEC3); Element Call's remote code is not
  pinned (NET-1); the SQLite advisory waits for an SDK update (FFI-11).
- **Not covered:** the QR login's new-device side against MSC4108
  (NET); the SDK's handling of huge sync responses (FFI).
